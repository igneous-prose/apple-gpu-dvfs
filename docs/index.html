DVFS ramp zone (16–768)

Small matrices under-utilize the GPU. DVFS stays at P3 (796 MHz) or ramps slowly. GFLOPS climbs from 1.8 to 290 — a 160× range driven mostly by frequency scaling + occupancy.

P15 plateau (1024+)

Once the grid saturates the GPU, DVFS locks at P15 (1578 MHz). GFLOPS stabilizes at ~554 — the ceiling of this tiled kernel (53% of theoretical 1010 GFLOPS FP32 FMA). Simdgroup MMA would push higher.

SRAM retention floor: The perf-states-sram table shows SRAM voltage holds at 780 mV for P0–P6 while GPU active voltage runs as low as 125 mV. From P7 onward, SRAM and GPU voltages match. This means the GPU's register file and on-chip SRAM cannot operate below 780 mV — the lower P-states reduce only the logic voltage, keeping SRAM data intact at the floor.
Observed DVFS Behavior
Binary switching

The CLPC controller is aggressive: light loads sit at P3 (796 MHz), and any substantial compute jumps directly to P15 (1578 MHz). Intermediate P-states are transient — used during ramp-up/down but not sustained. Power scales via clock/power gating within P15, not by stepping through P-states.

Power envelope

At P15, GPU power ranges from ~2.5 W (low-thread dispatches) to ~16 W (1M threads × 65K FMA iterations). The controller modulates power within P15 via per-core clock gating rather than downclocking to P12 or P10. This is Apple's efficiency play: one voltage rail, fine-grained gating.

Corner pair pattern

Each voltage corner (A–E) offers two frequencies: a "lo" (energy-efficient divider) and "hi" (max clock the silicon signs off at that voltage). The Δ increases with voltage — 104 MHz at 780 mV, 144 MHz at 980 mV — reflecting wider timing margin at higher voltages. The CLPC picks between them based on thermal headroom.

Implications for benchmarking

Kernel benchmarks on M4 GPU are effectively always at 1578 MHz once the dispatch is non-trivial. The DVFS contribution to variance is minimal — thermal throttling (not P-state stepping) is the primary noise source. Warm the GPU for ~2s before timing to ensure P15 lock-in.

Extraction Method
Device Tree — IORegistry
# Dump GPU device node properties
ioreg -l -w 0 -r -c AppleARMIODevice | grep -A200 '"compatible" = <"gpu,t8132">'

# Key properties:
  "perf-states"          = <...>   # 16 × 8-byte entries: [freq_Hz(u32), voltage_mV(u32)]
  "perf-states-sram"     = <...>   # same format, SRAM retention voltages
  "gpu-num-perf-states"  = <0f000000>   # 15 (little-endian)
  "perf-state-count"     = <10000000>   # 16 including idle
  "gpu-perf-base-pstate" = <03000000>   # P3 = 796 MHz base
Power Measurement — powermetrics
# Live GPU frequency + power + per-P-state residency
sudo powermetrics --samplers gpu_power -i 100 -n 100

# Output includes:
  GPU HW active frequency: 1578 MHz
  GPU HW active residency: 99.2% (338 MHz: 0% ... 1578 MHz: 99.2%)
  GPU SW requested state: (P1: 0% ... P15: 100%)
  GPU Power: 13421 mW
Decode perf-states blob
python3 -c "
import struct
blob = bytes.fromhex('000000007d000000807825146702000080eed524...')
for i in range(16):
    freq, mv = struct.unpack_from('<II', blob, i*8)
    print(f'P{i}: {freq/1e6:.0f} MHz  {mv} mV')
"
